## Scope

`CnStorePage` gains `canInstall`, `canPublish` and `publishRoute`, so the consuming app decides who sees Install and who sees Publish, and where Publish leads. With none of them set the page renders exactly as before: administrators see Install, nobody sees Publish.

Source: learniq decision D27 (27 September): any teacher installs a shared course as a copy; publishing is limited to a group in learniq's permission matrix, by default the team leads. The page only renders the answer; learniq resolves it server-side from its ADR-023 matrix.

## What changes

- `canInstall` and `canPublish`: `Boolean`, default `null`. `true` shows the button, `false` hides it from everyone including administrators, `null` keeps the administrator rule.
- `publishRoute`: a route name (string) or a vue-router location. Publish renders only when a route is set and publishing is allowed. The button navigates to the app's own publish surface and sends nothing itself (ADR-080 Decision 3: publish stays app-owned, like install).
- The internal `canInstall` computed became `showInstall` (a prop and a computed cannot share a name; nothing read it by name).
- Docs: new `docs/components/cn-store-page.md` with the props, the boot-time pattern for writing per-user answers into the page config, and a caution that visibility is not authorization. `docs/components/_generated/CnStorePage.md` regenerated with vue-docgen-cli 4.79.0 (the locked version); a control run on the unchanged tree reproduced every tracked generated file first.
- `l10n/nl.json`: no edit needed, "Publish" already carries "Publiceren".

No breaking change and no version bump. Every existing `type: "store"` page passes none of the new props. An older library ignores the keys, so learniq can write them before it upgrades.

OpenSpec: `openspec/changes/store-page-action-visibility/` (new capability `store-page`, REQ-STP-1 to 3). `openspec validate store-page-action-visibility --strict`: valid.
