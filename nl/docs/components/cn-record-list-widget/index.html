CnRecordListWidget

The objects of another schema that point at this record, drawn as the relation boards draw them. Registered under the record-list widget type.

A person page lists its open cases ("Verlichting fietspad Lindelaan", "2026-0082 · Woo-verzoek", a status pill, "Termijn 1 nov"), its latest contact moments (an icon by channel, a meta line, the summary) and its relations ("Secretaris van Buurtvereniging Oost"). Each is a list of another schema's objects filtered on a reference to this record. The source keys are those of object-list; what differs is the drawing.

Content shape​

{
  "type": "record-list",
  "title": "Zaken",
  "content": {
    "register": "my-register",
    "schema": "case",
    "filter": { "requester": "@objectId" },
    "sort": { "field": "deadline", "dir": "asc" },
    "limit": 5,
    "presentation": "rows",
    "title": "{title}",
    "meta": "{identifier} · {caseTypeName} · behandelaar {assigneeName}",
    "pill": { "field": "status", "labels": { "in_behandeling": "In behandeling" }, "colorMap": { "in_behandeling": "purple", "afgehandeld": "success" } },
    "trailing": ["Klaar {closedAt|date}", "Termijn {deadline|date}"],
    "rowRoute": "CaseDetail",
    "headerLink": { "label": "Alle {total} zaken bekijken", "route": "Cases", "query": { "requester": "@objectId" } },
    "emptyText": "Nog geen zaken"
  }
}

Source​

KeyMeaning
register, schemaThe list to read. Without both the widget sends nothing.
endpointSourceRead the rows from an app endpoint instead: { url, method?, params?, responsePath? }, the shape the object table and the stat tile take. The payload at responsePath is the array of rows; a payload that is not an array is an empty list. register, schema, filter and sort are then not used.
objectRowsList rows the page record holds instead: { path, where?, valuePath? }. The list at path, narrowed to the entry matching where, its valuePath taken; a JSON string is decoded. No request is sent: the record is the one the page read as the reader, so its read rules already apply (dossiq Onderzoek: { "path": "sensitiveProperties", "where": { "name": "onderzoeksstappen" }, "valuePath": "value" }). A tab counts the same rows with countObjectRows. refs ([{ field, register, schema, as }]) reads the record each row names in field and puts it on the row as as, so a contract line's productRef reads {product.name}; each record once, fifty at most.
filterField filters, with the @objectId, @object.<field> and @workspace.<key> tokens. While a required token has no value the widget sends nothing. An operator is an object: { "status": { "ne": "closed" } }.
sort{ field, dir }, sent as _order[field].
limitHow many rows to fetch and draw. Default 5.
offsetHow many rows of the list to skip first. Default 0. Two cards over one list read "next" (limit: 1) and "after that" (offset: 1) without a row twice. Not applied to a rank sort.
extendOpenRegister _extend[] values, so {assignee.name} reads a referenced object.
rowRouteA named route; each row links to it with params.id.
rowIdFieldDot path of the id the route receives. Default: the row's own id. A relation row links to its target with "to.id".

Drawing​

presentation is one of:

  • rows (default): title in bold, meta under it, a pill, a trailing text and a chevron. A row with a route is a link. In a detail page's side column the row stacks (title as a link, meta, then pill and date) and drops the chevron, which is the board's "Lopende zaken" card with limit: 1.
  • A rows row can lead with a short text in a 52px column before the title: leading is a template, such as "{submittedAt|time}" for the time of day, as board PtDashboard draws "Recente inzendingen". A row whose template does not fill draws no leading text.
  • pillAt: "start" draws a rows row's pill before its title instead of at its end, and ruleAbove: true rules above the first row too, as DqZaakDocumenten draws "Weigeringsgronden tot nu toe" (the ground's code, then its name, under a hairline).
  • A rows list can lead with an avatar: avatar is a name template ("{client.name}", or { "text": "{client.name}" }), drawn as a 36px circle with the initials of its first and last word ("Sanne de Vries" reads "SV"). A row whose name is empty has no circle. The second line is meta: "meta": "{client.name} · {channel}" with "extend": ["client"] puts the customer under the title. The circle is decoration (aria-hidden); the name is in the meta text.
  • avatar as { text, size: 32, tone: "primary" }: the initials on the primary tint, as board DqZaakGerelateerd draws a related case's type.
  • avatar as { text, size: 40 }: the person chip of a record card, 40px with the initials 16px bold on the grey ground, also in a detail page's side column (PqOrganisatie "Hoofdcontact").
  • rows with iconTile: true and an icon: each row leads with the icon in a 36px round tile, as board DqZaakTaken draws "Wat hierna komt".
  • feed: a round icon, a meta line and a text line. icon is an icon name, or { field, map, default } to pick one per row ("phone" to Phone).
  • inline: a label followed by the title, the title a link when rowRoute is set.
  • cards: a framed card per row in a grid of cards at least 240px wide, as board ShBank draws the bank accounts. The card shows the icon (only when you set one) and the title, with the pill and badges beside them, then the meta line, then trailing as a large figure. A card with rowRoute is a link. On a board-look dashboard the cards keep a 24px inset inside a titled card; give the placement borderless: true and showTitle: false to stand them on the page ground, as ShBank does.

Every text is a template. {path} reads a dot path off the row; {path|date} writes a date the board way ("1 nov", "18 nov 2025"), {path|datetime} adds the time ("4 okt, 10:52"). {path|relative} says "vandaag" and "gisteren" and then the short date, and {path|relativetime} adds the time of day ("vandaag, 09:42"). {path|ago} says how long ago it was: "10 min geleden", "1 uur geleden", then "vanochtend", "vanmiddag" or "vanavond", "gisteren", the weekday ("vrijdag") and after a week the short date. {path|week} is the ISO week ("Week 41"). A template with an empty token renders nothing, so trailing can list several and the first that fills is shown. Templates go through the host app's translate function first.

pill is { field, labels?, colorMap?, variant? }: the label comes from labels (translated) or the raw value, the colour from colorMap (keyed on the raw value, ignoring case) or variant.

One card, several sources (sections)​

sections draws several lists in one card, one after the other, as board DqZaakBetrokkenen draws the Toegang card: the case's access links, then the users and groups that can open the case. Each entry is a record list config of its own (endpointSource, avatar, title, meta, pill, rowAction, emptyText, errorText ...) and reads its own source, so a section that fails shows its own error text and the other sections stay. A section takes the card's other keys (presentation, ruleAbove, density ...) unless it sets them itself, and the card's footnote, footnoteVariant, footerLink and footerAction go under the last section only. The card's header event comes from the first section. Without sections the list reads its one source as before.

Three row options make such a section read like the board:

  • meta as { "cases": [{ "when": <condition>, "text": "via the case type" }], "text": "..." } writes the text of the first case whose when holds on the row (the condition vocabulary pill.cases uses, with contains for a list field and empty for a missing one), else its own text.
  • avatar.icon as { "field": "principal.type", "map": { "group": "AccountGroup" } } shows the icon in the avatar circle for a row whose field maps to one, and the initials otherwise.
  • hideWhen (a condition over the row) leaves out the rows it holds for, such as a service account among a case's grants. It applies to rows read from an endpointSource or from objectRows.

refusalText replaces the server's own words for a refused read (401 or 403) of an endpointSource: "Only the people this case is assigned to can see who has access". Any other failure still shows errorText.

A colour dot and flags​

dot draws a 14px colour dot before a row's title, as board DqZaaktypeOverzicht draws a case type's statuses: a field name ("dot": "color") whose value is the colour, or { "field": "tone", "colorMap": { "error": "var(--color-error)" } }. Only a hex, rgb()/hsl() or var(--…) colour is drawn. flags draws short labels at the row's end for the flags a row has: [{ "field": "isStart", "label": "Start" }, { "field": "isEnd", "label": "End" }] shows "Start" on a row whose isStart is true, and with value a flag holds when the field equals it. Labels go through the app's translate and join with " · ".

tiles: true (with presentation: "rows") draws each row as a framed tile, 8px 10px inside a hairline edge with radius 8, in a grid of 260px at the least and 8px apart, the title at 14px regular. Board DqZaaktypeOverzicht draws a case type's statuses this way: two columns of tiles, each with its colour dot and flags.

One action per row​

rowAction ends every rows row with one action, drawn as a 150px by 34px pill, as board DcMijnActies draws "Beoordelen" and "Stem uitbrengen". The title becomes the row's link (with rowRoute) and the chevron goes.

  • It is a manifest action plus a label: open-page opens that page for the row's id, navigate reads @object.<field> and @objectId off the row ("/votes/@object.id"). Both render as links. Any other type is a button that runs through the page's dispatcher: a handler gets the row as its last argument, open-modal gets it as the row prop.
  • variant: "outlined" draws it, in the board look on a dashboard, as an outlined button sized to its label, with the row title in the main ink (DqMijnTeam "Oppakken"). Without it the action keeps the pill.
  • labels: { field, map } picks the label per row: { "field": "status", "map": { "open": "Starten" } } reads "Starten" for an open item and label ("Afronden") for the rest.
  • endpoint (with method, default POST) makes it a button that calls that app URL for the row, as a rowActions endpoint entry does: @objectId and the row's {field} tokens filled in, the list read again afterwards, a refusal shown in the server's words (else errorText). A row whose labels entry is an empty string has no action, so DqZaakBesluiten shows "Herinneren" on an open advice request only.

Several actions per row, and links onwards​

rowActions ends every rows row that opens nothing with an actions menu (named by rowActionsLabel). An entry is a page action plus a label, dispatched as rowAction is (an open-modal gets the row as its row prop and its own props with @objectId resolved), or { label, endpoint, method? }: an app URL with the page's @objectId and the row's {field} tokens filled in. After an endpoint call the list reads again; a refusal shows the server's sentence as an alert (else errorText).

An entry can depend on the row. visibleWhen is a condition over the row ({ field, op?, value }, or all/any): the action shows only on rows where it holds, and a row with no action left has no menu. { label, href } is a link instead of a button. href is a template over the row ("{externalUrl}"). A web address opens in a new tab, and a path such as /apps/forms/s/{token} opens in place. Any other address hides the action on that row.

"rowActions": [
  { "label": "Fill in", "type": "open-modal", "target": "AnswerDialog", "visibleWhen": { "field": "instrumentKind", "value": "internal" } },
  { "label": "Open the form", "href": "{externalUrl}", "visibleWhen": { "field": "instrumentKind", "value": "external" } }
]

A set-field entry ({ type: "set-field", field, value, label, ariaLabel?, doneLabel?, errorText? }) is not in the menu: each row gets a button that writes field of the page's record with one PATCH, value read from the row ("{userId}"). The saved record goes back to the page (cnObjectContext.setObject) and the list reads again. The row whose value the record already holds shows doneLabel with a check instead of the button ("Assigned"). ariaLabel is a template filled from the row ("Assign to {displayName}").

footnote may be { path, text } instead of a text: it reads path of the same endpoint answer the rows come from (one request, through the endpoint cache) and fills {value} into text ("{value} matching colleagues at capacity"). It shows with no rows too, and not when the value is empty or zero. { source, text } reads the value from a request of its own instead (source in the endpointSource shape, page tokens filled in), for a fact that does not live in the rows' answer (DqTenant "Historie": "Kenmerk TEN-0014").

links ({ field, label, route, labelSource?, fallback? }) draws a line under the row naming the records at field ("Also on: 2026-0012 Parkeren, 2026-0031"). Each links to route with {value} the id; labelSource ({ register, schema, template }) reads their labels, ten at most, and fallback stands in until then.

A badge with kind: "count" ({ field, one, other }, {count} filled in) counts a list or a number on the row, and shows nothing at 0.

requiresApp names the app the rows come from. When it is not installed the list says absentText and reads nothing, so "not installed" is never shown as "nothing yet". intro is a line above the list. A template may be a list of candidates ("title": ["{summary}", "{subject}"]): the first that fills.

An action under the list​

footerLink (the shape of headerLink: { label, route, params?, query? } or { label, href }, {total} filled) ends the card with a text link under the rows, not drawn while the list is empty (DqDagAfsluiten "Naar Mijn werk", DqDashboard "Alles bekijken").

footerAction ends the card with one secondary button, also under the empty text, as board DqBezwaar draws "Beroep registreren" in its Beroep card. It is a manifest action plus a label and an optional icon, run through the page's dispatcher with the page's record as @object. disabledWhen is a visibleWhen condition (a field on the page's record, the workspace, an endpoint or a source; total reads the list's total): while it holds the button is disabled and disabledReason shows under it, tied to the button with aria-describedby. Label and reason go through the app's translate.

"footerAction": {
  "label": "Register appeal",
  "icon": "Gavel",
  "type": "open-form",
  "schema": "beroep",
  "disabledWhen": { "field": "decisionSent", "op": "neq", "value": true },
  "disabledReason": "Possible once the decision is sent"
}

footerAction.layout: "row" draws the note and the action in one ruled row, the action at its end. footerAction.note may be { path, lead } instead of a text: lead is a bold label before the note, and the note is the value at path of the same endpoint answer the rows come from (one request), shown while the list has no rows. Board DqZaak ends Zaakplan this way: "Doelen nog geen doelen: wat wil de verzoeker dat er verandert?" and "Doel toevoegen", the prompt read from the case type through the goals endpoint. Lead and value go through the app's translate.

Header​

On a card surface the detail page or the dashboard page draws the titled card. The widget reports its header through the header event, and the card shows it:

KeyMeaning
headerLink{ label, route, params?, query? } or { label, href }. {total} in the label is the list's total; params and query resolve tokens.
headerNoteA muted text in the same place, such as "{total} in totaal". {count:<field>=<value>} counts the loaded rows whose field reads that value: "{count:status=done} van {total} stappen klaar". It reads the rows the list loaded, so set limit to cover the list.
headerSubtitleThe muted line under the card title, with the same counts as headerNote: "{total} in totaal", "{count:status=completed} van {total} stappen klaar" (DqContact "Laatste contactmomenten", DqTenant "Inrichten").
headerCounttrue reports the list's total, which the dashboard card draws as a chip after its title ("Actiepunten 5").

In a tab panel there is no card header, so neither is drawn.

A table​

presentation: "table" draws a header row and one row per record. columns lists { label, value, align?, alertAbove?, sortable?, tone? }:

KeyMeaning
valueA template over the row, the cell text, or a list of templates of which the first that fills is shown (["{identifier} {title}", "{domain}"]).
align"end" right-aligns the cell, for numbers.
alertAboveA number above it reads bold in the danger colour.
sortableThe header becomes a button. The first press sorts the rows up, the next down. Numbers sort as numbers. The header carries aria-sort.
toneThe cell becomes a coloured label: { field?, map, default?, override? }. The value at field (else the cell text) picks a badge variant from map, else default. override: { when, tone } gives the cell tone while when, a condition over the row, holds.

A column's sub is a template drawn as a muted second line under the cell's text (board OrArchivering: the list's title, with "1.204 records" under it). It draws nothing when it fills empty.

rowActions works in the table too: the table ends with a column headed rowActionsHeader (default "Actions") holding each row's menu, with the same entries, visibleWhen and endpoint calls as the rows presentation. A row with no action left has an empty cell.

"columns": [{ "label": "List", "value": "{title}", "sub": "{summary}" }, { "label": "Status", "value": "{statusLabel}" }],
"rowActions": [{ "label": "Approve", "endpoint": "/apps/openregister/api/archival/destruction-lists/{uuid}/approve", "visibleWhen": { "field": "status", "value": "in_review" } }]

tone.override keeps a verdict from turning green on its own. This column is green for a compliant feature only when it is verified:

{ "label": "Verdict", "value": "{verdict}", "tone": { "map": { "compliant": "success", "violates": "error" }, "default": "default", "override": { "when": { "field": "verified", "op": "neq", "value": true }, "tone": "warning" } } }

indentPath names a number on the row, its depth in a tree. The first cell moves 16px in per level, so departments read under their school. With rowRoute the first cell links to the row's page.

flattenPath takes the rows from a list inside each record. With "flattenPath": "answers" every entry of a record's answers is a row, and {@parent.<field>} reads the record it came from. A record without the list adds no row, and {total} counts the rows drawn.

A meta line of parts​

meta as a string is one template: a row that misses one of its tokens gets no meta line at all. For a line built from fields that may be empty, list the parts: "meta": { "parts": ["{identifier}", "{caseTypeName}", "{handler.name}"], "separator": " · " }. Each part is filled on its own, the empty ones are left out and the rest are joined by separator (default " · "). A part can hold text and formats, such as "Termijn {deadline|date}".

States​

A list that asks for a personal lens (filter: { "_recent": true }) and gets none back because the lens could not answer says why in place of emptyText: "This server does not keep track of what you open.", "Log in to see what you opened recently." or "Your recent items are not available right now.". lensReasonTexts replaces the wording, keyed by <lens>.<reason> or <reason>, such as { "recent.audit-trail-disabled": "Recent cases need the audit trail." }; the text goes through the host's translate. A lens that is available, or a reason without text, keeps emptyText.

emptyText on one line when the list is empty; one quiet line (errorText, else "This list could not be loaded.") when the read fails, never both. The error goes to the console.

A label for a stored value​

valueLabels maps a field's stored values to labels the templates show: "valueLabels": { "channel": { "phone": "Phone", "telefoon": "Phone", "email": "Email" } } makes "{channel}" read the translated label ("Telefoon" for both spellings). A value the map does not name is shown as stored. The pill, the badges and the sort keep the stored value.

groupBy (a field path) draws the rows in groups, each under a heading (DqZaakGerelateerd: "Onderwerp van deze zaak", "Wacht op", "Gepland vervolg"). A heading is the field's valueLabels entry for the value, else the value, through the host translate. The groups come in groupOrder (a list of values) first, then in the order the rows bring them; the rows without a value come last, headed by groupEmptyLabel or not at all. Each group is its own list, named by its heading. Grouping applies to the list presentations (rows, cards, feed, inline); table, notice and notes ignore it.

groupLook: "cards" draws each group as its own card under an uppercase heading in the soft ink (PqMobiel). groupTones ({ "late": "error" }) tones the heading of the named group: error, warning, success or primary.

density: "compact" draws the rows 10px above and below, at least 56px tall, with the title at 500 instead of bold (DqProcesanalyse "Waar zaken blijven hangen"). Without it the rows keep their default spacing.

In rows, text is a muted line under the meta line ("text": "{idleDays} dagen stil", DqDashboard), left out when it fills empty. chevron: false leaves the chevron off a linked row; the row stays a link. The board look hides the chevron on a dashboard; chevron: true keeps it there (PqMijnWerk).

aggregates gives every row a figure over its related objects, as a table's aggregate column does: { "runningCases": { "register": "dossiq", "schema": "case", "op": "count", "where": { "caseType": "@self.id", "isFinalStatus": false } } } asks one _limit=0 count per row shown (op: "max" with field the highest value instead), @self.<path> in where read off the row, and the templates read it as {runningCases} (DqZaaktype Versies: "meta": "{validFrom|date} · {runningCases} running cases"). text ({ "zero": "no running cases", "one": "{count} running case", "other": "{count} running cases" }, translated) offers a count as words instead, so zero can read "geen lopende zaken". A failed figure is left out.

presentation: "checklist" draws the rows as a checklist in columns (1 to 4, default 3): a row for which done (a condition over the row, { "field": "status", "op": "eq", "value": "completed" }) holds is ticked, any other row is an empty circle, and a screen reader hears "Done" or "Not done yet" after each. progress: true adds a bar of the done share above it. With headerNote: "{count:status=completed} of {total} steps done" the card header counts them (DqTenant Inrichten "5 van 7 stappen klaar").

Page controls​

A list can follow the page's controls (a workspace-filter select and switch). Without pageControls it ignores them.

"pageControls": {
  "sort":   { "key": "sort", "map": { "deadline": { "field": "slaDeadline", "dir": "asc" }, "priority": { "field": "priority", "dir": "desc" } } },
  "toggle": { "key": "showDone", "removes": ["status"] }
}

sort: the workspace value at key picks an entry of map; a value with no entry leaves the list's own sort. toggle: while the value at key is on (true, 1, "1", "true"), the filter keys in removes are dropped, so a list that hides finished work shows it. The list fetches again when either changes.

Badges​

badges adds status badges after the row's pill. A field badge takes the same keys as pill (field, labels, colorMap, variant) plus hideValues, a list of values that draw nothing, so a priority badge shows for urgent and high and stays away for normal. look: "text" draws a field badge as words in its tone, without a ground (PqMijnWerk "Hoog priority" beside the kind pill). An age badge, { "kind": "stale", "field": "updatedAt", "afterDays": 7, "label": "Stale {days} days", "variant": "warning" }, shows when the date field is more than afterDays whole days old and replaces {days} with the age. pill.hideValues hides the pill the same way.

Due text​

due draws a date field as text with a tone: { "field": "deadline", "todayLabel": "Vandaag", "overdueLabel": { "one": "{count} dag te laat", "other": "{count} dagen te laat" }, "emptyText": "Geen deadline" }. A date before today reads the overdue label in the danger colour, today reads todayLabel (default "Due today"), a day to come reads "tomorrow" or the short date, and an empty field reads emptyText in the muted colour, or nothing without one. With upcomingLabel ({ "one": "nog {count} dag", "other": "nog {count} dagen" }) a day to come reads the days left instead of the date, and with upcomingWeeksLabel ({ "one": "nog {count} week", "other": "nog {count} weken" }) it reads the weeks left, rounded, from upcomingWeeksFrom days left (default 35). The texts go through the host's translate. The same keys work on a date column as widgetProps.due. In rows, duePlacement: "below" draws the due text as a line under the title (13px, in its tone) instead of at the end of the row (DqDagAfsluiten "Morgen eerst").

A bar under each row​

bar draws a thin track under each row of the rows presentation. With valueField alone the track is filled to the row's share of the largest row (board DqTeamwachtrij "Team vandaag": cases per colleague). With maxField it is filled to the row's value against its own maximum, and overVariant: "error" draws it in the error colour once the value is past that maximum (board PqWachtrij "Team vandaag": open tickets against maxConcurrent). The track is a meter named after the row's title.

{
  "avatar": "{displayName}",
  "title": "{displayName}",
  "meta": "{availability}",
  "trailing": "{open} open",
  "bar": { "valueField": "open", "maxField": "maxConcurrent", "overVariant": "error" }
}

Money​

{amount|currency} writes an amount as money, {amount|currency:USD} in the named currency, and {amount|currency:price.code} in the currency the row holds at that field. A row without a code, and the bare {amount|currency}, take the app's reporting currency (currency in the app config) and euros without one. The number follows the user's language ("€ 12.000,00" for Dutch). A row without an amount empties the template, as for every token.

Sort by the rank of an enum​

A text field sorts alphabetically on the server, so priority reads high, low, normal, urgent. A sort with rank puts the values in your order: "sort": { "field": "priority", "rank": ["urgent", "high", "normal", "low"], "then": { "field": "slaDeadline", "dir": "asc" } }, and the same object works as an entry of pageControls.sort.map. The list reads the rows one value at a time, best first, each group in the order of then, until limit rows are in; rows with another value or none come last. The rows shown are the first limit of the whole filtered list and {total} counts all of them. It costs up to one request per value plus two, where a plain sort costs one. A list whose filter already fixes the field ignores rank. Only the record list does this: the object table and index pages page through their rows and ignore rank.

Rows that are plain strings​

An endpoint may answer a list of strings (["…", "…"]). Each is read as { value }: a template reaches it as {value}, and a list without title shows the value itself.

presentation: "notice" draws the rows as one paragraph in a toned box (role="note"), after an optional lead with {total} filled in. variant is info (default), warning or error.

    "emptyText": "No warnings"
  }
}
