# CnFilesWidget

Files browser widget (folder navigation, thumbnails, mime filter, sort).

Part of the dashboard widget library (v2). Registered with the dashboard widget registry and consumed by MyDash/LaunchPad's widget grid. See [the widget library overview](./cn-widget-grid.md) and `docs/architecture/cards-and-widgets.md`.

## Object-bound mode

The widget has two modes, chosen automatically:

- **Dashboard mode** (default) — a placement/folder-scoped browser that reads from the host app's `{apiBase}/api/widgets/files/{placementId}/...` endpoints (`apiBase` defaults to `/apps/files`). This is the launchpad/mydash contract; unchanged.
- **Object-bound mode** — when `objectId`, `register`, and `schema` are all supplied (they are auto-merged by `CnWidgetGrid` from the detail-page object context), the widget instead binds to that OpenRegister object's Nextcloud folder. It renders a flat drop-zone/upload/delete surface backed by the object-file endpoints on `objectApiBase` (default `/apps/openregister/api`):
  - list — `GET {objectApiBase}/objects/{register}/{schema}/{objectId}/files`
  - upload — `POST {objectApiBase}/objects/{register}/{schema}/{objectId}/filesMultipart` (body `files[]`)
  - delete — `DELETE {objectApiBase}/objects/{register}/{schema}/{objectId}/files/{fileId}`

  In object-bound mode the upload and delete affordances are enabled by default (matching the object sidebar's Files tab); set `content.allowUpload` / `content.allowDelete` to `false` to hide them. `schema` accepts either a slug string or the resolved schema object (the slug is derived from `slug`/`id`/`uuid`).
