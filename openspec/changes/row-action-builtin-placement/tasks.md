### Task 1: Stable ids on built-in row actions
- **spec_ref**: `openspec/changes/row-action-builtin-placement/specs/index-page/spec.md#requirement-built-in-row-actions-carry-stable-ids`
- **files**: `src/components/CnIndexPage/defaultActions.js`, `src/components/CnRowActions/CnRowActions.vue`, `src/components/CnContextMenu/CnContextMenu.vue`, `src/components/CnIndexPage/CnIndexPage.vue` (`onRowAction`, `runPrimaryRowAction`), `tests/components/CnRowActions.spec.js`, `tests/components/CnIndexPage*.spec.js`
- **acceptance_criteria**:
  - Built-ins carry `id` (`view`, `edit`, `copy`, `delete`) and `builtin: true`
  - A built-in's testid is `cn-action-item-<id>` in a non-English locale; app action testids are unchanged
  - A built-in is keyed `builtin:<id>`; an app action with `id: "edit"` beside the built-in Edit renders both and each click runs its own handler
  - The `action` event payload keeps `action: <label>`, adds `id`, and adds `builtin: true` for built-ins only, with the `@event` JSDoc updated
  - Regression test over the three fleet patterns asserts order, render keys and English testids: `showViewAction: false` plus `{ id: "view", handler: "navigate" }`; openconnector's `id: "edit"` "Open editor" beside the built-in Edit; portaliq with Edit and Copy off and its own "Change"

### Task 3: The placement resolver
- **spec_ref**: `openspec/changes/row-action-builtin-placement/specs/index-page/spec.md#requirement-built-in-row-actions-can-be-placed-among-app-actions`, `#requirement-the-toggle-decides-whether-a-placed-built-in-renders`

- **acceptance_criteria**:
  - The OpenCatalogi example resolves to Edit, Copy, File list, Delete
  - Unplaced enabled built-ins are appended in View, Edit, Copy, Delete order; a page without placeholders renders exactly as before

  - A repeated placeholder renders once and warns; other strings are dropped with the existing warning; a `builtin` key on an object is ignored
  - Named-source `rowActions` go through the same resolver, with a test for a source placing `builtin:delete`
  - The resolver also reports whether Delete is last in the effective order, for reuse by Task 5
  - Table, list, card, context menu and the keyboard primary action follow the resolved order

### Task 4: Schema grammar
- **spec_ref**: `openspec/changes/row-action-builtin-placement/specs/index-page/spec.md#requirement-invalid-placement-strings-are-manifest-errors`
- **files**: `src/schemas/app-manifest-v2.schema.json`, `src/utils/validateManifestV2.compiled.js` (regenerated by `npm run build:validators`), `tests/utils/validateManifest.builtinPlacement.spec.js` (new)
- **acceptance_criteria**:
  - `config.actions.items` accepts the object shape or one of the four placeholders; the description states the placeholder rule
  - One `contains` / `minContains: 0` / `maxContains: 1` per placeholder refuses repeats; two identical objects still validate
  - The object shape refuses an `id` matching `^builtin:` and any `builtin` key
  - A page-level `allOf` branch refuses strings in `config.actions` on non-index pages
  - `builtin:archive` and `edit` fail schema validation; the schema `version` is bumped
  - `config.actionToggles` declares `showViewAction` beside the other row action toggles, since turning View off is how a page keeps it from being appended after a placed Delete
  - All cases are asserted through `validateManifest()` on v2 fixtures (`$schema` ending in `app-manifest-v2.schema.json`), and once through Ajv2020 against the raw schema as apps' `check:manifest` does
- [x] Implement
- [x] Test
