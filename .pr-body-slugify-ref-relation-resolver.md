## Scope

OpenRegister resolves the objects API by schema slug (kebab-case), but a `$ref` on a schema property is authored as the referenced schema's title (`ReportPeriod`, not `report-period`). Every resolver in this library that turned a `$ref` into an objects-API path built it from the raw title, so any multi-word schema 404s while a single-word one works by accident. This is learniq round-1 defect 7 (128 properties across 52 schema titles; `ReportCardDetail` renders with every relation panel blank because of it). The fix adds one helper, `schemaRefSlug()`, and routes the three resolvers that build objects-API paths from a `$ref` through it: `schema.js`'s `normalizeRef()` (feeds every `CnFormDialog` reference picker), `CnObjectDataWidget.vue`'s `relationProp()` (the related widget, the exact site of the `ReportCardDetail` defect), and `actionsDispatcher.js`'s `resolveObjectOpType()` (the shared resolver behind `CnFkResolveCell`, used by `CnObjectListWidget`'s grouped headers, `CnCellRenderer`'s `fkResolve` cell widget, and several other widgets).

No breaking changes: `schemaRefSlug()` is a new export, all three fixed functions keep their existing signatures, and the conversion is idempotent, so every caller that already passes a correct slug is unaffected.
